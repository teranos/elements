# elements
[AXIOMAS.md](AXIOMAS.md) — read it before changing anything here. [VISION.md](VISION.md) — why the axioms exist.

An element is exactly one DOM element for its entire lifetime. It morphs between forms — dot, proximity-expanded, window, panel, canvas — through smooth animations, but the element identity never changes.

This package is the element runtime: tray, proximity engine, morph transactions, forms, and the canvas interaction layer (drag, resize, meld). It has zero framework dependencies — pure DOM, Web Animations API, and dependency injection via `configureElements()` and `CanvasHost` for host-specific concerns.

## Core pattern

Every element renderer follows the same shape: take an `Element`, return a DOM element.

```typescript
import type { Element } from '@teranos/elements';

function createMyElement(item: Element): HTMLElement {
    // build DOM from item.id, item.title, item.content, item.symbol
    // return a single element — the element's identity for its entire lifetime
}
```

The `Element` interface is the universal input contract. The package owns the type; renderers live in the host.

`title` is plain text — strip any markup before passing. `symbol` is the one symbol field and the package renders it natively: generic title bars, canvas-placed title bars, and the proximity-expanded dot all display it, through `createSymbolSpan`. `symbolElement` is the element-continuity carrier for the same string across a cursor → placed morph.

## Environment

Browser-only. Assumes `document`, `DOMParser`, Web Animations API, and `ResizeObserver` as globals. Not compatible with Node.js or SSR without a DOM polyfill.

## Configuration

Host apps call `configureElements()` at startup to inject logger, persistence, canvas coordinate bridge, `CanvasHost`, and cleanup callbacks. `CanvasHost` bridges canvas interaction (drag, resize, meld) to host-specific state — persistence, selection, composition CRUD, and sync. Without configuration, safe defaults apply: no-op logger, no-op persistence, no-op canvas host, identity coordinate transforms, and no meld table, so nothing melds.

`dotGeometry` is the exception to "host-specific concerns": it is geometry, not a dependency. The proximity engine writes the dot's width, height and border-radius inline on every frame, so no stylesheet can reach it — a host that wants a bigger or smaller dot sets it here. Left unset, a dot rests at 13px on a phone (up to 768px wide), 15px up to 900px, 10px above. The tray's place at the right edge, its column, the gap between dots (2px, 6px on a phone) and a dot's glide between sizes are the package's too, written inline; a host's stylesheet gives only the dot's font, text colour and border colour.

```typescript
configureElements({
    dotGeometry: { minWidth: 15, minHeight: 15 },  // resting dot; omitted fields keep the screen's resting size, 220/32/2
});
```

[JSR](https://jsr.io/@teranos/elements) holds every published version. Every push to main publishes, tests gating it, from `.github/workflows/publish.yml`. JSR skips a version it already has without a word, so the workflow fails instead when `version` in `jsr.json` has not moved: a commit on main either ships or is red.

## Boundary

Where this package ends and a host begins. The test that settles each line is in [CLAUDE.md](CLAUDE.md).

- 「[Sonnet 5.5] **Canvas workspace orchestration is the host's.** Pan, zoom, selection, and what has been spawned are the host's to wire to its own persistence and sync. The package owns the interaction layer the workspace consumes: drag, resize, meld, placement, z-order, touch browse, the spawn menu.」
- **The spawn menu is the package's; what can be spawned and what becomes of it are the host's.**
  "on mobile, can't get into spawn menu"
  「[Sonnet 5.5] A right-click, or a finger held still for half a second, on any element carrying `data-canvas-id` opens the menu where it was pressed, and the host has no listener to wire: the nearest canvas is the one asked. What the menu looks like, how a choice is carried to where it is put down, how it is cancelled (Escape, a right-click, or, because a phone has neither, another hold), and the morph that puts it down are the package's (`canvas/spawn.ts`, `canvas/touch-hold.ts`). The host says `configureElements({ spawn })`: which entries a press offers (`entries`, plain text, none meaning no menu), and what becomes of the choice (`place`). `place` renders into the element it is handed and returns that same element; an element is one DOM element for its whole life, so another one is an error, said, and the carried one does not stay behind. Ids, persistence and pan and zoom stay the host's. A hold is a hold until its finger lifts, whatever time has passed: the lift of the finger that opened the menu sends no mouse events after it, so the menu does not take it for a press outside itself.」
- **How elements meld is the package's; which kinds meld, and on which side, is the host's.** Ports, one connection per side, meld options and composition layout are the package's (`canvas/meld/`). The table of element classes and their ports comes from `configureElements({ meldability })`; without one, nothing melds.
- **A canvas is the element carrying `data-canvas-id`.** Drag, meld, and the window ↔ canvas morphs find the canvas an element stands on by that attribute, and its value is the id the host is asked about. The package knows no host class name for it.
- **ElementUI's I/O is the host's.** `pluginFetch`, `pluginWebSocket`, `onMeld`, and config persistence belong to the host factory. The DOM building blocks (`createInput`, `createButton`, `createStatusLine`) are package-owned in `canvas/ui-primitives.ts`; the host factory delegates to them.
- **Titles arrive plain.** Callers strip markup before passing items.
- **Where a window stands while the keyboard is up is the package's; how its fields look is the host's.** A window with a focused field rises clear of the on-screen keyboard and goes back after (`window/keyboard.ts`), because placement is the package's.
- **That a tap on a field brings the keyboard and nothing else is the package's, and the host has no say.** "You tap a box to type, and the only thing that should happen is the keyboard coming up. Nothing on the screen should move, zoom or refocus." A field inside an element is at 16 whatever a host writes (`text.ts`), the size iOS Safari does not zoom the page for; the page's scale is the person's, and the package leaves the host's viewport line as the host wrote it. (It once held `maximum-scale=1`; in a Chromium phone that took pinch zoom away, a pinch of 2.5 leaving the scale at 1.) It holds where the page stands too (`position.ts`): while a field has the keyboard, the window goes back to where it stood when the field took focus, whatever scrolls it. It answers the keyboard on a page the person has pinched too: a pinch alone makes the visual viewport smaller (screen over scale) and moves nothing, and what it is short of what it showed when the field took focus is the keyboard's (`window/keyboard.ts`, `keyboardTakes`; not `innerHeight`, which Safari shrinks with the keyboard; the before only rises while focus moves between windows, goes when no keyboard is up or the screen turns, and a keyboard already up that this page did not raise leaves a pinched page unanswered, as there is nothing to compare with). No host has to remember anything for it, and none can turn it off. The real keyboard run dresses its field small and fails if the page zooms. An editor is a field that is not a tag: a `contenteditable` surface inside an element (CodeMirror's) is at 16 too, and the text written in it. An open shadow root inside an element gets the same rule, as an adopted stylesheet a host's `innerHTML` cannot wipe (a style element where a browser has none): found when the root is in the element as it is held or added, and, for one attached to a host already there, when a finger or a focus lands in it, before the keyboard or a zoom. When the element rests as a dot the root is the host's again. In a root the package takes off an inline size and leaves layout alone, a root having no fit rule of the package's. A closed root nobody can reach, and a field outside an element is the host's to size.
- **A panel on a touch screen has no title bar row; the package's, and no page makes it one.** "Inefficient use of space." Its title and minimize button said nothing the grabber and the swipe do not. The bar is the grabber's 16px strip, written important; the swipe to the tray is taken there, and the minimize button is kept for a screen reader, unseen (`forms/panel.ts`, `foldToStrip`). Out of a panel, the bar is a row again.
- **A screen's size classes are the package's: Compact and Regular, by width and by height.** "Let's support Compact and Regular" (Apple Human Interface Guidelines, Layout). The edges are Material's window size classes' compact edges: under 600 wide is Compact width, under 480 high is Compact height; a phone held upright is Compact wide, held sideways Compact high. `sizeClasses()` says them, and `COMPACT_WIDTH` and `COMPACT_HEIGHT` are the media queries (`compact.ts`). A table's `regular` columns follow the width class. The tray's spacing for a finger keeps its own edge (768 wide): it is about a finger, not a size class.
- **Text size inside an element is the package's, entirely; the host picks from its sizes.** "Text size needs to be owned by Elements entirely and misuse should result into compilation error." The sizes are `TEXT_SIZES`: xs 10, sm 11, md 13, lg 14, and text is at sm until said otherwise. They follow the person's text size, and only the person's: the browser's own default, what `font-size: medium` measures ("Be prepared for text-size changes", Apple HIG, Accessibility). The package measures it once, in a closed shadow root of its own where no rule of the page reaches, and writes each size as a number, the package's number times that scale and never less; a host's root font-size, a custom property or a rule on its spans moves none of them (`text.ts`, `personScale`). A field (`input`, `textarea`, `select`) is at 16 (`FIELD_TEXT_SIZE`), whatever is around it: under 16, iOS zooms the page when it is tapped. The one way to size text is `sizeText(node, size)`, and a size not in the set does not compile (`TextSize`); a caller with no types gets a `TypeError`. What the compiler cannot see, a host's stylesheet (important or not), a style attribute or an em, is inert inside an element: the package puts one layered, important rule in the page, and a size written in a style attribute inside an element, important or not, is taken off as it is written (`text.ts`). A dot's symbol is the tray's and not sized by it.
- **That nothing runs off an element's edge is the package's, and the host has no say.** "This, I never want to have happen": a status line in a panel on a phone ran off the edge, and since nothing scrolls sideways, what did not fit was gone. Inside an element text breaks to the width it has, a word too long for it anywhere in it (`overflow-wrap: anywhere`, in the same layered, important rule as text size, `text.ts`). A host's `overflow-wrap` or `word-break` changes nothing. Text a host holds on one line (`white-space: nowrap`) it still holds.
- **Content wider than its element drops the element dead; the package's, and the host has no say.** Wrapping text was not enough: a row held on one line, a table cell, a button row or a fixed width still ran past the edge, cut off, with a warning nobody read. Now, measured on every change and every change of width, an element whose scroller holds content wider than itself hides that content where the host put it, says in a notice how wide in how wide and which nodes reach past the edge, and logs it as an error until the content fits; then it is alive again (`content/scroll.ts`, `dropDeadIfTooWide`). `expectFits(element)` fails a host's browser test on the same measure.
- **What a host writes fits its element; the package's, and the host has no say.**
  "no element should have content that isnt accesible"
  Dropping dead names what does not fit; the fit makes it fit (`fit.ts`). Text wraps where a host held it on one line, a box is no wider than what holds it, a table divides the width it has, a grid's tracks give way, a box placed past the edge is brought inside. A flex row wraps once it runs out of room, or squeezes what is in it below what it holds, measured, and not before: a row that fits stays one line, and what is in it keeps the height the row gives it, so a scroller in a row still scrolls.
- **A button is as wide as what it says; the package's, and the host has no say.**
  "Button should never take up element full-width"
  A column that stretches, a grid cell, `width: 100%` or `flex: 1` made a press as wide as its element. Inside an element a button is `width: fit-content` and does not grow or give way, written in the layered, important rule, and a host's important width on it is taken off (`fit.ts`). What is beside it gives way instead.
- **A window that holds more than a window may is a panel; the package's, and the host has no say.**
  "situations like this, the Element should just open full screen like a panel"
  「[Opus 5.5] Whether an element opens as a window or a panel was asked once, of what it held when it opened: a node's answer still on its way, so a "Loading…" was measured and it opened as a window that its content then outgrew. A window sized by what it holds now asks again as what it holds arrives, measured as it was at opening, and once it holds more than a window may take it is a panel, its content carried (`window/window.ts`, `fitsAsWindow`). What arrived while it was still opening is asked about as it settles. A window a person gave a size stays theirs.」
- **The presses of a list stand in one place; the package's, and the host has no say.**
  "buttons in row's should be consistnetly placed and alligned"
  Each row wrapped on its own, so a long name dropped its press to the left while the rest stayed right. The rows of one list wrap together (`fit.ts`, `wrapRows`).
- **The presses of one list are one size; the package's, and the host has no say.**
  "buttons not being the same size SUCKS"
  A button as wide as what it says made a list of them as many widths as it had labels. Buttons stacked in one holder, or the one button of each row of a list, are as wide as the widest of them says, measured (`fit.ts`, `evenButtons`).
- **A press and a field look as the ax element does, canvas-placed; the package's, and the host has no say.**
  "so, QNTX wide, buttons need to look more like the ax element"
  "the way the ax element looks when its canvas-placed"
  "the high contrast is for approvals element only"
  The ax element's query field is the look: its ground, its ink, the canvas-placed frame's outline, a 2px corner (`forms/ax.ts`, `AX`). Armed, a press fills with the ink, red or green as before. The approvals draw their own presses, in high contrast.
- **No field in an element is left unstyled; the package's, and the host has no say.**
  "ban unstyled inputfield"
  A field of several lines is a field too (`fieldFrom`, `lines`). A field a host made by hand inside an element wears the field look all the same, written in the layered, important rule (`fit.ts`); the chat's field is its own.
- **A flow is seen through to the end; the package's, and the host says only its steps.**
  "there is actually a kind of distinction Anthropic does well here"
  "which is to accept that this is a 1,2,3,4 flow, and needs to bee seen through until the end."
  As Anthropic's Connect workload wizard is: numbered steps down the side, each named with what it is, one drawn at a time, a scrim over everything under the window it stands in. Continue is never greyed out: on a step not done it says what the step still needs, and stays. The last step says Done, and Done is the only way out (`forms/flow.ts`, `flowFrom`).
- **A window stands whole on its screen; the package's, and the host has no say.**
  "i cant even use the mail element on desktop"
  "if it overflows width, hard fail, die"
  A window sized by what it holds grew with what arrived after it opened, from where it stood, past the screen's edge: content never ran past the window, so the drop-dead measure saw nothing. Now a window that would run past the right edge slides back, and one wider than the screen is the screen's width and wraps what it holds; past the bottom it slides back up, and one taller than the screen is the screen's height: as it settles, as what it holds grows, as anything writes where it stands, and as the screen changes (`window/settle.ts`, `holdOnScreen`). `expectFits(element)` fails an element that runs off its screen, not only content that runs off its element.
- **A window's size, once a person gives it one, is the person's; what it holds fills it.** "want to be able to rezise it and have it actually respect my resize, horizontally and vertically." Dragged by its corner, or reopened at the size it was dragged to, a window's content fills its body both ways, written important: a host's fixed size on its content does not leave it small in a window dragged big (`window/resize.ts`, `fillWithContent`). Before a drag the content is the size its host draws it, and the window measures it.
- **Where an element opens in its scroller is the package's; that it opens at its end is the element's to say.** "claude element should not start at top when opening requiring user to scroll down every single time." An element saying `opensAt: 'end'` opens scrolled to what was said last, in its own scroller, and follows what is said after while it is at the end; scrolled up, the person is left reading (`content/end.ts`). Xenon is the specimen. An element that opens at its end says so, `data-opens-at="end"`, so a host's gate can hold every one of them to it without knowing which they are.
- **What a chat says with is one pill; the package's shape, the host's choices.** "Why not do it like anthropic does, where its a combined model+effort pill", "We don't need to show the picker always". `choicesFrom` reads what is chosen, joined (`Opus 5.5 · high`); pressed, a sheet above it lists each choice's options; an option taken is what it reads, the host is told, and the field has the words again. Given to a say field (`declareSay(field, { choices })`) it stands above the pill only while something is being said: the field focused or holding words, or its sheet open (`content/choices.ts`, `content/say.ts`). Which choices, and what they do, are the host's.
- **Every text in an element reads at 4.5 to 1; the package's colours are held to it.** "Text is not readable like this." An element's words are its paint, as its background is (`paint.ts`): a dot wears its `textColor`. What is typed into the pill is the element's colour, a placeholder its field's own ink, lighter, both in the package's layer so a host still says otherwise (`fit.ts`). Yes and no read as words on black and as a fill under white words (`MEANS`). The examples are held to it in a real browser (`browser/contrast.browser.ts`).
- **A button in an element is never squeezed around its words; the package's.** "NO MORE SQUEEZED BUTTONS PLEASE", "buttons of elements have the same issue". In an element's body a button is a finger tall (`FINGER`, a press's height) with its words an em in from each side, whatever the host wrote (`fit.ts`). A press, a say press and the title bar's controls keep their own boxes.
- **Where a chat's field sits and what shape it is are the package's; which field it is and what it looks like, the host's.** "making the inputfield take up the entire bottom of the screen for chat elements like claude or pi." A host declares the field its element says from (`declareSay`); the row stays at the bottom of the element, in the element's colour, while what was said scrolls above it; what the host put beside the field wraps above it. Written important (`content/say.ts`). A field the host draws after the element opened is held when it arrives. Its presses make it the Claude app's composer (`declareSay(field, { start, end })`): "This i want", "I want this only", "LOOK AT THIS THE SHAPE". One pill as wide as the body, the + at its start, what is typed, the → at its end, on one line; its presses `SAY_PRESS` square and round, `SAY_INSET` in from its edge, whatever they hold (`fit.ts`). Its colours, border and icons are the host's. On a phone the home bar's strip is the page's, under the pill, and nothing of it while the keyboard is up (`forms/panel.ts`, `window/keyboard.ts`).
  "i think chatfield soudl be considered different from regular inputfied"
  `sayFrom` makes the chat's field, the package's own: lines of text, named by its label, declared the element's. Xenon is the specimen.
- **Where an element scrolls is the package's; what scrolls is the host's to say.** An element scrolls vertically in one place (Apple HIG, Scroll views: no scroll view inside another of the same orientation): the body the package gives it, or a node the host names with `declareScroller()`, and the body then stops scrolling and makes room for it: the body's child holding it is bounded by the body, and from there down the host's layout carries the bound. Whatever the package does for scrolling it does there. Any other vertical scroller in an element is named — `data-scroller="undeclared"` and one warning saying what to do instead — and fails `expectScroll()` in the host's tests (`content/scroll.ts`). Sideways scrollers and a field's own scrolling are not second scrollers. The package's own table (`createTable`) is one: wider than its element it scrolls sideways in its own box and nothing around it does (WCAG 2.2, Understanding 1.4.10 Reflow: a data table is exempt, in its own scrollable container). Text in it breaks between words, a time, a DID, a status and a head hold their line, the box is named and is a tab stop only while it scrolls (`table.ts`). A host's own table is still fitted to the element's width, equal columns. A column `createTable` is told is `regular` is not shown on a Compact screen.
- **The scrollbar is the package's, the only one.** "i want one cemtrally managed elements owned scrollbar and they the elements are only allowed to use that one" — "there should not be a system one" (#2). Inside an element no system scrollbar is drawn, whatever a host's stylesheet says (layered and important); the element's scroller shows the package's bar, one per element, unseen by a screen reader, and a mouse can drag it (`content/scrollbar.ts`).
- **A sparkline's drawing is the package's; what its numbers mean is the host's.** `renderSparkline` and `wireLineTooltips` draw and say a line, coloured by `--elements-sparkline-*`; buckets, units and labels come from the host.
- **A table's shape and look are the package's; what each cell says and what a press on a row opens are the host's.**
  "The elements package should own Tables"
  `createTable` builds the heads and rows under one class, `element-table`, and puts its stylesheet in the page once; a cell is text, or a cell the host built whole (`tableCell`, or its own `td`).
  "TABLES BEING MAX 4 col." A table has one to four columns (`MAX_TABLE_COLUMNS`), and every row is as wide as its heads: a fifth column, or a row of another width, does not compile (`TableHeads`, `TableCells`); a caller with no types gets a `TypeError`.
- **A press's size, look and stages are the package's; what it does is the host's.**
  "a button should just be the same size"
  "the immediate red communicates, irrevocable click, which is wrong for this."
  `pressFrom` is Button Form's variation that does rather than opens: its name (`id`, written `data-press`), its title and what a second press does (`again`). It is part of the element it sits in and never a second element in it, so nothing that finds an element by `data-element-id` finds a press. "I just want a preselection of sizes": a press is one of `PRESS_SIZES`' boxes, a width and a height, and nothing in it decides how big it is, not its title, not what it is doing, not what it says. Which box is the package's to pick, by the form the press stands in (`pressSizeFor`): small in a window or on a canvas, middling in a panel, a workspace or an expanded canvas, large on the bare page. The box is the package's layered rule's, written important, so no host stylesheet or style attribute sizes it; its title holds to two lines of it. What the second press does, and a failure, are said beside it, never in it. It is square with a 2px outline, on whatever surface it stands on: "how discordant the black button is compared to everything else". At rest it is outlined white whatever it does; armed, "To be clear that you're arming the button and can then press to confirm", it is filled with what its outline says: white, red only when its second press cannot be undone (`irrevocable`), and green and shimmering only when it creates (`creates`), "press once to check, button becomes green and shimmers, 2nd click actually creates it", and a bar runs out across its foot for as long as it waits. ElementUI's `createButton` is a press too: there is no other button. A single press cannot be irrevocable, or create: that, or a colour or a size chosen by the host, does not compile (`forms/press.misuse.ts`), and a caller with no types gets a `TypeError`.
  "foutmeding at the inputfield makes sense for example"
  A press is never disabled: held back (`hold(why)`) it is greyed and `aria-disabled`, still reached by a keyboard, and pressed it says why beside it. What `does` could not do because of a field it throws as `AtField(field, ...)`, and it is said at that field, which is marked invalid and points to it.
- **A field is the package's; what it asks for is the host's.**
  "and elements should own all inputfields"
  `fieldFrom` is one line of text with its label shown above it and tied to it, as tall as a finger, dressed as a press is. A field varies only by the keyboard a phone brings up (`KEYBOARDS`: text, email, tel); anything else is a `TypeError`. Selenium is the specimen.
- **An overlay is over one other element; the package's, and the host says only which.**
  "THE OVERLAY IS A NEW ELEMENT FORM"
  "AND IS ALAYS ASSOCIATED WITH ONE OTHER ELEMENT"
  `overlayFrom` rests an element over the one the host names, bottom left, its ground slightly transparent, and refuses what is no element. A drag moves it, no further than that element; a press opens it fullscreen, a panel, the same element. Minimized, swiped down or left by Escape it comes back to where it rested and never to the tray (`forms/overlay.ts`, `forms/home.ts`). What it says at rest (`says`) and when it is gone (`away`) are the host's. Astatine, over Polonium, is the specimen.
- **An approval's choosing is the package's; what a press does is the host's.** "Do you hear how little it matters what the 'thing' is to approve?" `renderApprovals` shows the list, every option, the confidence the fast classifier answers, the checks and the time in the buttons, and the roll's order; every press is handed to the host (`pressed`), which says what the checks are doing (`checks`) and when what stood took effect (`settled`). An aside (`asides`) opens what the host hands it and chooses nothing. Merging, mailing, creating an account: the host's.

## Morph classes

One morph class, `morphing`, belongs to the morph: `prepareMorphTo` adds it beside the element's own classes, and the transaction ends it — commit swaps it for the settled classes (`panel …`, `canvas-fullscreen-adjusted`; a window settles into none, `[data-form="window"]` is its only hook), rollback restores exactly the classes the element had. Which form is in flight is `data-form`'s to say, written at morph start. Position and stacking during a morph are inline, and `raise()` writes a plain z-index.
